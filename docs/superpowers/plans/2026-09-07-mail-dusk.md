# Pile mail perso et notifications dusk — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** lire son courrier personnel dans `aerc`, et voir le nombre de messages non lus dans la barre `dusk` avec ouverture du client au clic.

**Architecture :** `mbsync` synchronise l'IMAP vers un Maildir local toutes les 3 minutes via un timer systemd user ; `aerc` lit ce Maildir et envoie par `msmtp` ; un script `mail-sync` détecte les nouveaux fichiers et notifie via dunst ; le module de barre ne fait que compter des fichiers locaux, sans aucun accès réseau.

**Tech Stack :** `isync` (mbsync), `aerc`, `msmtp`, `rbw` (client Bitwarden), systemd user, `dusk` / `duskc`, GNU stow, shell POSIX.

**Spec :** `docs/superpowers/specs/2026-09-07-mail-dusk-design.md`

## Global Constraints

- **Aucun secret dans le dépôt.** Les configs ne contiennent que `rbw get mail-perso`. Le mot de passe vit dans Bitwarden, le coffre qu'Emmanuel utilise déjà.
- **Phase 1 = un seul compte**, le serveur perso. Gmail, gmx, yahoo et hotmail sont hors périmètre (spec §13).
- **Scripts en `#!/bin/sh`**, dans le style de `bin/.local/bin/statusbar/rssmod/`.
- **Commentaires et messages de commit en français**, comme `bin/.local/bin/suckless-build` et les commits récents (préfixe de portée : `mail:`, `doc:`, `fix:`).
- **Pas de framework de test.** Chaque tâche se termine par des commandes de vérification dont la sortie attendue est décrite.
- **Slot de barre : 11.** Maildir : `~/.local/share/mail/<compte>/`.
- **`~/.local/bin` est un lien replié** vers `dotfiles/bin/.local/bin` : un nouveau script y est actif immédiatement, sans re-stow. Ce n'est **pas** le cas de `~/.config/systemd/user` ni de `~/.local/share/applications`, qui sont de vrais dossiers contenant des liens individuels — y ajouter un fichier exige `stow -R`.

## Structure des fichiers

| Fichier | Responsabilité |
| --- | --- |
| `mail/.config/isyncrc` | où est l'IMAP, où atterrit le Maildir. **Ce chemin exact** : `mbsync` lit `$XDG_CONFIG_HOME/isyncrc` puis `~/.mbsyncrc`, et rien d'autre — un fichier rangé sous `isync/mbsyncrc` ne serait jamais trouvé, et il faudrait passer `-c` partout |
| `mail/.config/msmtp/config` | comment partent les messages |
| `mail/.config/aerc/aerc.conf` | apparence et rendu du client |
| `mail/.config/aerc/accounts.conf` | le compte, adossé au Maildir local |
| `bin/.local/bin/mail-sync` | synchroniser, détecter le neuf, notifier, rafraîchir la barre |
| `bin/.local/bin/statusbar/mailmod/mail` | compter les non lus, sans réseau |
| `bin/.local/bin/statusbar/mailmod/mail_click` | les cinq boutons du segment |
| `systemd/.config/systemd/user/mbsync.{service,timer}` | cadence de la synchro |
| `mimeapps/.local/share/applications/aerc.desktop` | handler `mailto:` |

**Écart assumé par rapport à la spec §3 :** pas de `binds.conf` en phase 1. `aerc` retombe sur `/usr/share/aerc/binds.conf` quand le fichier utilisateur est absent ; en livrer une copie identique n'apporterait rien et créerait une divergence à maintenir. On en ajoutera un le jour où un raccourci est réellement modifié.

```
# Synchro IMAP -> Maildir local pour le courrier personnel.
#
# Le mot de passe n'est jamais ici : PassCmd le tire de Bitwarden via rbw.
# Ce fichier est donc publiable tel quel.
#
# Lu par mbsync, appele par ~/.local/bin/mail-sync (timer mbsync.timer).
# Ajouter un compte = ajouter un bloc IMAPAccount / IMAPStore /
# MaildirStore / Channel, rien d'autre a toucher.

IMAPAccount perso
Host mail-fr.securemail.pro
Port 993
User emmanuel@farcis.fr
PassCmd "rbw get mail-perso"
TLSType IMAPS
CertificateFile /etc/ssl/certs/ca-certificates.crt

IMAPStore perso-distant
Account perso

MaildirStore perso-local
Path ~/.local/share/mail/perso/
Inbox ~/.local/share/mail/perso/INBOX
SubFolders Verbatim

Channel perso
Far :perso-distant:
Near :perso-local:
Patterns *
Create Both
Expunge Both
SyncState *
```

`TLSType IMAPS` correspond au port 993 retenu. Le certificat de `mail-fr.securemail.pro` a été validé nom d'hôte compris, donc aucun contournement TLS n'est nécessaire — si un jour il en faut un, c'est le signe d'une erreur de nom d'hôte, pas d'un certificat à ignorer.

### Task 5 : `mail-sync` — synchro, détection, notification

**Files:**
- Create: `bin/.local/bin/mail-sync`

**Interfaces:**
- Consumes: `mbsync -a` (tâche 3), le module de comptage de la tâche 6 s'il existe déjà (appel toléré absent).
- Produces:
  - le fichier d'horodatage `~/.cache/statusbar/mail_sync`, contenant l'epoch de la **dernière synchro réussie**. La tâche 6 le lit pour décider du suffixe `!`.
  - code de retour `0` en succès, `1` si `mbsync` échoue, `0` sans rien faire si un autre exemplaire tourne déjà.

- [ ] **Step 1 : Écrire le script**

Créer `bin/.local/bin/mail-sync` :

```sh
#!/bin/sh
# Synchronise le courrier et signale les nouveaux messages.
#
#   mail-sync          synchronise, notifie, rafraichit la barre
#   mail-sync --quiet  synchronise sans notifier (premiere synchro, cron)
#
# Appele par mbsync.timer toutes les 3 minutes, et a la molette haut sur le
# segment courrier de la barre.
#
# Comment le neuf est detecte : on liste les fichiers de */INBOX/new avant et
# apres mbsync ; les noms apparus sont les nouveaux messages. Pas de base, pas
# d'etat a maintenir — le Maildir est deja la source de verite.
#
# En cas d'echec de mbsync : aucune notification (un reseau coupe n'est pas un
# evenement digne d'un popup toutes les 3 minutes) et l'horodatage n'est pas
# mis a jour, ce qui fait apparaitre le suffixe « ! » dans la barre au bout de
# 30 minutes. Le detail est dans journald : systemctl --user status mbsync
#
# Surchargeables pour les tests :
#   MAIL_ROOT     racine du Maildir
#   MBSYNC_CMD    commande tenant lieu de mbsync
#   NOTIFY_CMD    commande tenant lieu de notify-send

set -u

maildir="${MAIL_ROOT:-${XDG_DATA_HOME:-$HOME/.local/share}/mail}"
cache="${XDG_CACHE_HOME:-$HOME/.cache}/statusbar"
stamp="$cache/mail_sync"
lock="$cache/mail_sync.lock"
# Surchargeables pour les tests, comme firefox-profile-handler.sh et mdview le
# font deja : sans ca, verifier la detection du neuf imposerait de s'envoyer de
# vrais messages et d'attendre, ou de couper le reseau.
MBSYNC_CMD="${MBSYNC_CMD:-mbsync}"
NOTIFY_CMD="${NOTIFY_CMD:-notify-send}"
quiet=0

case ${1-} in
    --quiet)   quiet=1 ;;
    -h|--help) sed -n '2,20p' "$0" | sed 's/^# \?//'; exit 0 ;;
    "")        ;;
    *)         echo "option inconnue : $1 (voir --help)" >&2; exit 2 ;;
esac

mkdir -p "$cache"

# Le timer et la molette de la barre peuvent tomber en meme temps : le second
# arrivant repart sans rien faire plutot que de lancer un mbsync concurrent.
exec 9>"$lock"
flock -n 9 || exit 0

tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

inventaire() {
    find "$maildir"/*/INBOX/new -type f 2>/dev/null | sort
}

inventaire > "$tmp/avant"

if ! $MBSYNC_CMD -a >"$tmp/log" 2>&1; then
    sed 's/^/mbsync: /' "$tmp/log" >&2
    exit 1
fi

inventaire > "$tmp/apres"
comm -13 "$tmp/avant" "$tmp/apres" > "$tmp/nouveaux"

date +%s > "$stamp"

# Rafraichir la barre sans attendre le prochain tour de sa boucle.
compteur="$HOME/.local/bin/statusbar/mailmod/mail"
[ -x "$compteur" ] && duskc --ignore-reply run_command setstatus 11 "$("$compteur")" 2>/dev/null

[ "$quiet" -eq 1 ] && exit 0

n=$(wc -l < "$tmp/nouveaux")
[ "$n" -eq 0 ] && exit 0

# Les en-tetes encodes (=?UTF-8?B?...?=) sont illisibles bruts dans dunst.
decoder() {
    perl -MEncode -CS -pe '$_ = Encode::decode("MIME-Header", $_)' 2>/dev/null \
        || cat
}

entete() {
    # $1 = fichier, $2 = nom de l'en-tete. S'arrete au corps du message et
    # recolle les lignes de continuation (RFC 5322 « folding »).
    awk -v h="^$2:" '
        /^$/ { exit }
        tolower($0) ~ tolower(h) { found = 1; sub(/^[^:]*:[ \t]*/, ""); print; next }
        found && /^[ \t]/ { sub(/^[ \t]+/, " "); print; next }
        found { exit }
    ' "$1" | tr -d '\n' | decoder
}

# Au-dela de 3, un popup par message noierait dunst.
if [ "$n" -gt 3 ]; then
    $NOTIFY_CMD "✉ Courrier" "$n nouveaux messages."
else
    while read -r f; do
        [ -f "$f" ] || continue
        $NOTIFY_CMD "✉ $(entete "$f" From)" "$(entete "$f" Subject)"
    done < "$tmp/nouveaux"
fi
```

- [ ] **Step 1 : Écrire le compteur**

Créer `bin/.local/bin/statusbar/mailmod/mail` :

```sh
#!/bin/sh
# Nombre de messages non lus, tous comptes confondus. Aucun acces reseau :
# on ne fait que compter des fichiers deja sur le disque, ce qui rend le
# module utilisable dans une boucle de barre a la seconde.
#
# Non lu, au sens Maildir : tout fichier de INBOX/new, plus tout fichier de
# INBOX/cur dont les drapeaux (apres « :2, ») ne contiennent pas « S » (Seen).
# Seule INBOX est comptee — ni le spam, ni les archives.
#
# Le suffixe « ! » signale que la derniere synchro reussie remonte a plus de
# 30 minutes : un compteur perime doit se distinguer d'une boite vide. C'est
# aussi pour ca qu'on affiche « ✉! » quand le total est nul mais la synchro
# en retard, alors qu'un zero a jour n'affiche rien du tout.

maildir="${MAIL_ROOT:-${XDG_DATA_HOME:-$HOME/.local/share}/mail}"
stamp="${XDG_CACHE_HOME:-$HOME/.cache}/statusbar/mail_sync"

[ -d "$maildir" ] || exit 0

neufs=$(find "$maildir"/*/INBOX/new -type f 2>/dev/null | wc -l)
lus_partiels=$(find "$maildir"/*/INBOX/cur -type f 2>/dev/null | grep -cv ':2,[A-Za-z]*S' || true)
total=$((neufs + lus_partiels))

perime=""
if [ -r "$stamp" ]; then
    age=$(( $(date +%s) - $(cat "$stamp") ))
    [ "$age" -gt 1800 ] && perime="!"
else
    perime="!"
fi

if [ "$total" -gt 0 ]; then
    printf "✉%s%s" "$total" "$perime"
elif [ -n "$perime" ]; then
    printf "✉!"
fi
```

`Terminal=false` avec `kitty -e` dans l'`Exec` : c'est `kitty` qui fournit le terminal, on ne veut pas que le lanceur en ouvre un second.
